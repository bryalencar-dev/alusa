2) Rotas disponíveis (públicas e protegidas)
Públicas (sem middleware de auth):
- / (apps/web/app/page.tsx)
- /auth/login
- /auth/register
- /auth/forgot-password
- /health (API)
- /api/auth/[...nextauth] (fluxo do NextAuth)
- /api/first-register (setup inicial)
- /api/upload (depende de auth no handler; não há middleware global)
- /api/test/users-count (apenas em teste)

Protegidas via middleware (matcher '/admin/:path*'):
- /admin/dashboard
- /admin/alunos
- /admin/configuracoes
- /admin/professores
- /admin/academicos
- /admin/academicos/alunos

Outras rotas de app não cobertas pelo middleware (mas podem checar sessão no server/client manualmente):
- /dashboard
- /configuracoes
- /recepcao/alunos
- /(recepcao)/professores -> faz redirect para /admin/professores

APIs protegidas (checagem de sessão/role no handler):
- /api/alunos (GET, POST)
- /api/alunos/[id] (GET, PATCH, DELETE)
- /api/professores (GET, POST)
- /api/professores/[id] (GET, PATCH, DELETE)

3) middleware.ts (autenticação e bypass de testes)
- Usa withAuth do NextAuth com pages.signIn = '/auth/login'
- Se TEST_ROUTES_ENABLED === 'true', o middleware é bypassado (útil para E2E)
- Export config: { matcher: ['/admin/:path*'] }
  => Apenas rotas /admin/* passam pelo middleware automaticamente.

4) Sidebar/Menu (components/dashboard/Sidebar.tsx)
- Sidebar estática (lista fixa de grupos e itens)
- Itens apontam para rotas /admin/*, incluindo:
  - Dashboard (/admin/dashboard)
  - Acadêmicos: Alunos, Professores, Turmas, Matrículas, Presenças, Avaliações
  - Financeiro, Aulas, Relatórios, Loja, Eventos, Configurações
- O destaque “ativo” é calculado por pathname.startsWith(href)
- Não há filtro dinâmico por role aqui; o RBAC é aplicado no backend (APIs) e via middleware (acesso às páginas /admin/*)

5) Páginas duplicadas ou em mais de uma pasta
- /admin/professores: agora centralizada em (dashboard)/admin/professores/page.tsx
- Existia admin/professores/page.tsx (removida) e (recepcao)/professores/route.ts (removida)
- (recepcao)/professores/page.tsx permanece apenas como redirect para /admin/professores para compatibilidade de links antigos.
- Existem, por design, pares como /admin/alunos e /recepcao/alunos (rotas diferentes). Isso não é duplicação de arquivo; são seções distintas do produto.

6) Páginas de autenticação
- /auth/login (apps/web/app/auth/login/page.tsx)
- /auth/register (apps/web/app/auth/register/page.tsx)
- /auth/forgot-password (apps/web/app/auth/forgot-password/page.tsx)
- Layout de auth em /auth/layout.tsx

7) RBAC (alto nível)
- Middleware protege /admin/* (exige sessão; redireciona para /auth/login se não logado)
- Handlers das APIs de alunos e professores fazem checagem de role:
  - Permitido: 'ADMIN' e 'RECEPCAO'
- getSessionUser em apps/web/lib/auth/session.ts resolve user.id, role e contaId.

8) Notas finais
- O grupo (dashboard) é um route group para organizar arquitetura; ele não altera a URL final (por isso /admin/professores aparece sem o segmento).
- Professores: página final em (dashboard)/admin/professores; formulário é importado de (recepcao)/professores/ProfessorForm.tsx.
- Em caso de erro de rotas duplicadas, reiniciar o dev server geralmente limpa o cache do watcher.
